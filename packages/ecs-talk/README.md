# ecs-talk

A [NorthTalk](https://github.com/odogono/odgn-talk) Host Adapter for an `odgn-ecs` World.

```ts
const talk = createEcsTalk(world);
talk.loadAtomScript('person', source);
gameLoop.addSystem('talk', talk.system); // systems, then the Pump, then flush
```

- **`entity` Object Kind:** each registered component is an optional property. Reading one gives its map, or Nothing when the entity doesn't have it. `set` replaces the whole component and validates it, so an invalid value fails the Run.
- **Handles:** `talk.handle(eid)` makes the entity's Host Object the first time it is needed, with its parent already set, so a Script that reaches an entity inside a Run can send to it in that Run ([odgn-talk ADR 0152](https://github.com/odogono/odgn-talk/blob/main/docs/adr/0152-a-host-object-may-be-given-its-parent-when-it-is-made.md)). Once an entity is deleted, its Handle reads as Nothing. The next Pump after the deletion is flushed drops the Handle.
- **Message Path:** an unhandled message climbs through every base atom that has a Script. The Lineage is linearized: each base, rightmost first, then that base's own bases, with an atom reached twice kept only at its last place. So `vase: box fragile`, where both are built on `thing`, climbs fragile, box, thing. A Host Object has one parent, but one atom can sit on several paths with different atoms above it, so each such position gets a Host Object of its own that owns a copy of the atom's Script (named `atom@path`, with timers kept under the atom's name). Copies don't share Script Variables.
- **Elements:** the entities whose `location.in` is this entity, in id order, each named by `meta.props.id`.
- **`world` Capability:** `find place, component` returns a list of Handles, and `resolve id` turns an entity id, such as an `s.entityId()` field, into its Handle (Nothing if there is no such entity). `change thing, component, value` replaces a component, validated as `set` is. `change`, `moveTo thing, place` and `show actor, text` are Host Commands. `show` publishes a `talk:show { actor, text }` event.
- **Segment-bound writes:** `change` and `moveTo` join the Run's Segment, through an `odgn-ecs` Change Scope. When the Segment commits, the writes are flushed on the tick; when it rolls back (a Limit Fault, Stop, cancellation or Rewind), the World keeps no trace of them, so a Rewound Run dispatched again writes once. As NorthTalk specifies, a Run that ends in an uncaught ordinary error still commits. While a Segment is open, another Run's write to an entity it changed fails with `world busy`. A property `set` can't join a Segment, so it is immediate: prefer `change` for writes that must roll back.
- **`clock` Capability:** `ask clock to now` gives the Pump's Clock reading as an Instant.
- **`timer` Capability:** offered when the World registers `talkTimerComponent`. `tell timer to schedule name, at, message, args` stores a durable timer as an ECS entity, replacing one of the same name, and `tell timer to cancel name` removes it. Each Pump first delivers the timers now due, so timers outlive the adapter: a new adapter over the same World fires them. A timer belongs to the entity its Run was delivered to, not to the Script: one atom's Script serves every entity built from it, so names are scoped to that entity and the Script, and the message is delivered back to the entity. The entity is found from the call's `delivery` ([odgn-talk ADR 0125](https://github.com/odogono/odgn-talk/blob/main/docs/adr/0125-a-host-functions-call-names-the-delivery-that-started-its-run.md)), so a Run started by a Script's own `send`, which has none, can't set a timer. A timer whose entity has been deleted is dropped. A Host can keep its own timers in the same store: `talk.schedule({ owner, script, name, at, message })` stores one under a `script` name of its own, and the `onTimer` option, given each timer as it falls due, returns true for the ones it handles itself.
- **Libraries:** `talk.addLibrary(name, source, imports?)` registers a NorthTalk Library, stateless shared code that Scripts import with `use fn from name`. Add it before the Scripts that use it.
- **Service Scripts:** `talk.loadServiceScript(name, source)` loads a Script owned by a Host object of its own, not an atom, so no entity's Message Path reaches it. Send to it with `talk.requestService(name, message, ...args)` or `talk.decideService(...)`, passing the entities it acts on as arguments. A Host can write its core behaviour this way without changing any entity's Message Path. Its Grants are an atom Script's.
- **Decisions:** `talk.decide(eid, message, ...args)` asks the entity's Message Path, and its `decided` promise settles with the Verdict after the Pump.

In an atom's Script, `me` is its Owner (the atom's own Host Object), and `the target` is the Receiver (the entity the message was delivered to). The Receiver stays the same while the message climbs the path. Write `set the stats of the target to {…}`, not `… of me`.
